# 双端原型与候选交互（ITERATE r5 草稿）

原型位于 `../prototype/`，包含独立 Vue 3 用户端和管理员端。用户端遵循 [design-user.md](../../../../../design-user.md) 3.2，管理员端遵循 [design.md](../../../../../design.md) 2.2。本文件定义候选行为，不登记验证结果。

用户端保留白色画布、绿色主题、横向导航及 r4 的线性图标、按钮和轻量标签。来源只显示名称，“更新简报”保留 WandSparkles。r5 删除阅读标记与整理记录，采用新闻详情弹窗和简洁生成进度，进入网站即建立匿名身份。

## 用户端

| 路由/入口 | 用户能做什么 | 关键状态 |
| --- | --- | --- |
| 网站首次访问、`/login` | 自动创建或恢复匿名账号 | 采用 r2 欢迎页视觉展示自动进入、加载、失败重试；无邮箱、密码和注册表单 |
| `/onboarding` | 一页填写话题、背景、关键词 | 未配置的新匿名账号进入；保存失败留在当前页，成功持久化完成标记 |
| `/today` | 今日新闻、话题筛选、更新简报 | 无内容、生成中保留旧简报、进度与预计剩余时间、部分完成、失败 |
| `/briefs` | 搜索、筛选、翻页查历史简报 | 无历史、无结果；返回保留筛选 |
| `/briefs/:id` | 阅读一期新闻列表 | 保留内容与来源；无运行记录、技术参数或阅读状态 |
| 单条新闻 | 标题/阅读详情按钮打开对应新闻弹窗 | 显示摘要、推荐理由、时间、来源与引用；Esc/关闭后回到触发元素 |
| 头像 → `/settings/preferences` | 编辑话题、背景、关键词 | 至少一个话题或关键词；显式保存、失败留草稿、未保存离开提示 |
| `/settings/schedule` | 只设置每日自动推送时间 | HH:mm 校验、保存中和失败重试；仅站内推送 |

`/settings` 默认到偏好，旧 `/preferences`、`/delivery` 保留重定向。旧注册入口并入自动进入流程，旧 `/runs/:id` 不再提供详情，转回今日。匿名账号没有退出登录或切换为密码账号的入口。

网站启动先确保服务器匿名 Cookie 会话，不能使用前端伪造身份代替。有效 Cookie 恢复同一用户及首次配置状态；Cookie 丢失或真正过期创建新身份并重新引导，不承诺恢复旧历史。封禁响应保持当前身份并提示不可用，不自动清 Cookie；限流显示等待提示，不无限重试。欢迎页的恢复仅指旧视觉，不恢复旧注册/密码行为，此处理已获用户明确确认。

话题与关键词命中任一即可作为原型候选内容；至少一个话题或关键词，背景最多500字、关键词最多20个且每个最多40字。原型窗口24小时、最多10条和全部来源是系统默认值，背景仅保存供正式Agent理解，不伪装语义推理。

## 详情与生成

新闻标题和阅读详情按钮是可键盘触发的弹窗入口；原文链接独立处理，点击来源不再叠加弹窗。弹窗只显示当前条目，保留推荐理由及出处，不跳至整期替代单条详情。内容可滚动，焦点限制在弹窗内，关闭恢复焦点；手机宽度下不溢出视口。

删除“标为已读/未读”“只看未读”以及阅读数量/状态；不再提交相关接口。历史简报仍可阅读，站内“已发布”只表示内容已发布。

用户只看公开生成状态、进度条和预计剩余时间，不显示模型、工具、阶段、子任务、日志或整理记录。百分比和时间由服务端公开投影提供：未知为 `null`，展示不定进度/“正在估算”；时间是估计而非承诺，可以更新，不能本地倒计时归零后宣告成功。服务端确认完成才显示结果入口，失败可重试，刷新可恢复当前生成。取消能力仍留在服务/管理层，不恢复用户运行详情页。

## 管理员端

管理员维持深青绿、暖白、侧栏和表格风格，独立登录；匿名用户不可进入管理功能。

| 路由 | 操作 | 状态 |
| --- | --- | --- |
| `/login` | 独立管理员演示认证 | 加载、失败，不能使用匿名Cookie |
| `/overview` | 看运行、来源和发布异常 | 无样本不制造完成率 |
| `/sources`、`/sources/:id` | NewsNow/RSS周期、启停、模拟采集 | 上游周期、失败保留有效快照、下次到期 |
| `/models` | 端点、角色、key、连接测试 | 秘密不回显，失败保留非秘密字段 |
| `/agent-configs` | 参数、提示词、工具和子Agent配置 | 保存草稿/发布版本，新运行生效 |
| `/runs`、`/runs/:id` | 查看脱敏运行、工具事件、摘要与子任务 | 取消、失败、文件冲突；事件均标明模拟 |
| `/evaluations`、`/evaluations/:id` | 固定样例实验和比较 | 排队、失败、评分未知，不假装真实准确率 |
| `/users` | 匿名账户监测与配额、封禁/解封 | 请求率、每日生成、并发、限流、风险、脱敏IP与事件；失败不报操作成功 |
| `/deliveries` | 处理站内发布故障 | 重试同一期，发布与未知状态分开 |

匿名策略默认60请求/分钟、20生成/日、1并发、10新账号/IP/小时。范围分别1–600、1–100、1–10、1–100，必须为整数。监测页面解释风险与限制原因，限制由服务端执行；封禁与解封需可追溯记录。正式策略变更的管理员审计是后端验收项，当前原型不冒充已实现。清Cookie不重置IP新号门槛。管理观察Agent细节的能力保留，用户端关闭这些入口不会影响开发者调优。

## 原型边界与验证

新闻、Agent运行、评估和站内发布均为synthetic。r5仅新增开发服务 `/__demo` 演示服务器Cookie、账户计数及封禁；本地JSON不是生产MySQL，生产FastAPI、真正调度和Agent均待实施。用户与管理员开发页面通过该服务共享匿名监测；其他模拟业务数据仍由集中adapter管理，不能声称全部双端已接真实后端。

体验路径：自动进入 → 首次订阅 → 今日生成进度 → 单条新闻详情 → 头像设置；管理端独立登录 → 监测匿名账户 → 修改配额/封禁 → 用户请求受限 → 解封后正常请求。浏览器需验证失败重试、Cookie刷新恢复、429/403、弹窗键盘与手机排布。实际结果记入阶段证据，当前仍ITERATE、未冻结。
