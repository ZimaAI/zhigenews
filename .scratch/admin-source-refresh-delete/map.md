# 管理员新闻来源刷新与删除进度优化

Type: research
Status: resolved

## 已明确的需求

- 自动刷新等待响应时，管理员仍可正常操作；刷新不能覆盖用户输入或操作结果。
- 一键删除期间展示实际进度，列出已删除和已跳过的新闻来源。
- 删除执行中禁止再次发起一键删除；结束后恢复入口。
- 继承 docs/adr/0001-delete-source-collection-history.md 的删除范围与影响。
- 用户已确认两轮共八项建议，完成共享理解确认后进入实现；实现及验证见 spec.md 和 verification.md。

## 代码事实

- Sources.vue 每 5 秒尝试刷新，后台刷新复用 loading，导致勾选、分页、搜索提交与批量操作禁用。
- source-list.ts 已有 AbortController 和请求 revision，可扩展用于阻止旧响应覆盖写操作结果。
- listSources 每页返回 10 条，但读取全部来源统计 invalidTotal。
- batch_sources 逐项取非阻塞来源文件锁，清理文件与数据库记录，完成整个调用后返回结果。
- 未取得来源锁时返回 SOURCE_BUSY 并继续处理其他项；采集与删除使用相同来源锁。
- 已入队采集任务执行时发现来源不存在会返回 missing，不会重新采集。
- security.authenticated(lock=True) 对当前管理员 User 行使用 FOR UPDATE；gateway.execute 的普通请求在同一事务中鉴权及执行业务。现有整批删除因此长时间持有该行锁，同账号其他请求存在等待该事务的路径。此项为代码确认，未进行并发耗时实测。

## 采用的方案

- 分离首次加载与后台刷新；保留列表、选择、输入草稿，写操作开始时使旧读取失效，结束后重新同步。
- 删除请求返回任务标识，后台逐项处理并持久化结果；只有文件清理及该项数据库事务提交后才报告删除成功。
- 状态接口返回总量、处理数量、各项结果和原因；进度按已处理数量计算，不将跳过算成删除成功。
- 可采用短轮询获取进度；如需事件即时推送，可采用 SSE，但传输方式不代替持久化任务状态。
- “有进度”和“删除更快”分别验收；历史数据查询和文件清理的耗时占比尚未测量。

## 第一轮已确认（2026-09-20）

1. 关闭、刷新或离开页面后继续删除，返回页面恢复查看进度；任务仍在执行时，不能再次发起删除。
2. 全系统同一时间只允许一个来源批量删除任务，所有管理员与标签页共享该限制。
3. “删除所选来源”与“删除全部失效来源”共享进度和互斥规则。
4. 固定任务创建时的候选来源集合。全量删除失效来源时逐项重验失效状态；已恢复或锁被占用的来源跳过，本轮不反复重试，新增失效项留待下次。

领域术语已补入根 CONTEXT.md，架构决定见 docs/adr/0002-background-source-deletion.md。

## 第二轮已确认（2026-09-20，用户回复“全部按建议”）

5. 删除期间其他操作：建议允许查看、筛选、翻页和操作非目标来源；待处理及正在处理的目标暂不允许编辑、启停或手动采集，终结项按实际结果恢复可用操作。
6. 进度体验：建议页面内固定区域，每秒查询一次任务状态（不重叠请求），显示总处理进度、各结果计数及名称/原因明细；完成后保留最近一批结果直到下一批开始。
7. 中断处理：建议浏览器断线只停止观察，服务端工作进程重启后从已记录结果继续；单项失败记录后继续其他项，无法继续的整批任务明确失败结束，不永久占用入口。
8. 编辑并发：建议刷新不覆盖编辑草稿；其他管理员已修改同一来源时，提交提示冲突并保留草稿，来源已删除则明确告知，不无声覆盖较新修改。

## 已核实的复用边界

- 现有 Celery 与事务 Outbox 可扩展删除任务投递；可能重复投递，执行须识别已完成项。
- Run / RunEvent 和 SSE 当前绑定简报运行语义，不直接挪用为来源删除任务；轻量状态轮询是候选最小方案。
- 来源文件锁应覆盖单项清理及数据库提交；进度必须反映已提交结果。

## 实现补充

- 活动任务每秒查询进度，无活动任务时每五秒检查其他管理员是否启动任务。
- 未处理项在整批异常结束后显示“未处理”，不计入处理进度；正在清理但未确认完成的项记为失败。
- 文件清理失败继续沿用原有规则：来源停用，残留清理未完成时需要重试删除，不能以启用或编辑绕过未完成的文件清理。
