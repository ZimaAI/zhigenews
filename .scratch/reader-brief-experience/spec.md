# 用户端简报生成与阅读体验

Status: 已实现并完成开发验证；本地服务已更新。真实模型的写作质量尚未进行人工验收。

## 用户已明确的目标

- 生成过程中，让用户持续感知任务仍在进行，减少暴露的信息量。
- 今日页生成结束后，只呈现成功或失败的结果，不展示内部执行细节。
- 历史简报不展示“部分完成”字段，阅读是主要任务。
- 简报标题像报纸标题，简要概括本期新闻，不包含运行窗口、索引等后台数据。
- 简报导语精简概括本期内容，不呈现检索过程、执行报告或用户无法理解的系统信息。
- 每条新闻摘要使用简短、通俗易懂的语言。
- 优化 Agent 提示词，使输出直接面向读者。

## 第一轮已确认决策

- 生成反馈使用少量真实、通俗的阶段及持续轻量动效；只随真实进展变化，不展示日志、工具名或虚构百分比。
- 简报标题用一句报纸式概括；导语用 1–2 句说明本期重点；单条摘要用 2–3 句说明发生了什么及值得关注之处，无可靠依据时不补充意义。
- 不写检索窗口、索引数量或执行过程，保留影响事实理解的必要限定，例如“尚未公布”“据某方称”。
- 写作规则只对新生成内容生效，历史列表隐藏状态标签，已有标题、导语与新闻摘要不自动改写。

## 当前约束

- 用户调用 grill-with-docs，按 grilling 与 domain-modeling 进行分轮讨论并记录确定事项；达成共同理解后再实施。
- 沿用用户端视觉与共享组件；`design-user.md` 已同步本次确认的反馈与阅读规则，替代原百分比、预计剩余时间及用户可见部分完成规则。
- 工作区已有 `apps/user-web/src/components/GenerationProgress.vue` 未提交修改，需在其基础上处理。
- 访谈建议不等同于已确认决策。

## 代码核查发现

- 内部部分完成由缺失来源与限制说明决定，与新闻条数无直接关系；新闻列表为空时也可能正常结束。因此需单独明确空结果语义。
- 当前 Agent 输出没有独立的读者导语字段，详情摘要由限制说明拼接而来。新方案需要独立生成并传递面向读者的导语，内部限制说明不再充当正文。
- 用户端通过轮询获取进度，现有数据缺少公开阶段，断连后不会自动继续轮询。
- 当前 Agent 会交替研究与推理，不能将事件误读为严格单向的“检索→筛选→写作”。真实阶段应由明确业务节点提供，不把上下文压缩或普通模型调用标作写作。
- 当前百分比和预计时间通常不可用，结束落库和发布时才出现固定百分比值。
- 当前正式应用处于 v1.0.0 / FRONTEND_VERIFY；本次讨论针对正式应用，不修改隔离原型或已封存基线。

## 第二轮已确认决策

- 流程正常完成但无相关新闻时，提示“本次未发现符合偏好的新内容”，属于正常完成；保留旧简报，不新增空白历史记录。
- 去掉百分比与预计剩余时间，仅保留真实阶段和持续轻量动效；同阶段耗时较长时提示“仍在整理，请稍候”，不按计时器假装进入下一阶段。
- 生成失败时保留旧简报，显示“生成失败，请重试”并提供重试入口。
- 暂时无法获取进度时显示“正在重新连接”，自动恢复后继续跟踪同一任务，不将断连当成任务失败。
- 刷新或离开后返回时恢复真实任务状态，不重复创建任务。

## 完整方案

### 生成反馈与结果

| 场景 | 用户体验 |
| --- | --- |
| 等待开始 | 简短准备文案，持续轻量动效，防止重复提交。 |
| 正在运行 | 展示当前真实业务阶段，例如“正在查找和整理新闻”；不承诺不存在的严格单向检索、筛选、写作步骤。 |
| 终稿已完成、正在保存发布 | 根据真实业务节点展示简短收尾阶段，发布完成后才显示更新成功。 |
| 同阶段等待较久 | 保持进行中反馈，提示“仍在整理，请稍候”；不虚构工作量、百分比或剩余时间。 |
| 进度请求暂时中断 | 显示“正在重新连接”，恢复后继续原任务，不显示虚假的活跃阶段变化。 |
| 成功得到可读简报 | 显示“简报已更新”并更新内容；内部 completed/partial 不再形成用户可见的两种完成等级。 |
| 正常完成但没有符合条件的新闻 | 提示“本次未发现符合偏好的新内容”；保留原内容，不新增空简报。首次生成也没有内容时保留简洁空态。 |
| 生成失败 | 显示“生成失败，请重试”和重试入口，保留上一份简报。 |

生成反馈只展示用户当前需要知道的状态，不显示原始错误、来源缺失清单、限制说明、模型、工具、日志或运行编号。身份失效等必须由用户处理的访问问题仍按现有必要提示处理，不伪装成持续生成。

### 历史与阅读

- 历史列表保留日期、标题、新闻条数、搜索与筛选，去掉生成状态标签。
- 新标题概括新闻重点，避免堆砌话题、重复的简报前缀、运行日期和后台参数；新闻事实本身必要的日期可以保留。
- 新导语用 1–2 句概括本期内容；单条摘要用 2–3 句白话概括事实，保留必要归属和不确定性，不自行补充结论。
- 新闻来源、发布时间和原文入口继续保留，摘要精简不改变来源追溯。
- 旧标题、导语、单条摘要保持原样；隐藏旧记录的状态标签不触发历史内容重写。

### 实现落点

- Agent 结构化输出增加独立的读者导语；内部限制说明继续承担诊断用途，与读者内容分开。
- 更新实际生效的 Agent 主提示词、字段说明及收尾约束，确保标题、导语和单条摘要使用相同的写作规则。
- 在可靠业务节点提供面向用户的阶段；普通模型调用、工具次数和上下文压缩不充当完成比例或写作阶段。
- 调整空结果的保存与发布逻辑，正常结束无内容任务时不生成空白历史，也不替换旧简报。
- 调整用户端进度组件、任务恢复、自动重连与历史列表，沿用已有未提交修改。
- 内部运行状态与管理员诊断信息保留，不为用户显示简化而改写内部 partial 为 completed。

## 验收标准

1. 生成全程有当前状态与轻量动效，无百分比、预计剩余时间或内部细节；阶段只由真实业务事件推进。
2. 运行期间旧简报可读；刷新、离开返回和暂时断连后继续同一任务，不重复生成。
3. 可读的部分完成简报在今日页显示成功，历史无状态标签，内部诊断仍可保留。
4. 正常完成但新闻为空时不新增历史、不覆盖旧简报；首次空结果也有明确简短反馈。
5. 真正失败时显示简短失败文案和可用重试入口，不泄露原始异常。
6. 新导语来自读者导语字段，限制说明不进入新标题、导语或新闻摘要；已有正文不批量改写。
7. 用代表性新闻检查标题概括性、导语 1–2 句和摘要 2–3 句的白话表达及事实归属；检查移动端、键盘、状态播报及减少动效偏好。
