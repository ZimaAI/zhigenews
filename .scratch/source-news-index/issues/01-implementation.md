# 来源新闻索引与 Agent 自主检索

Type: task
Status: resolved
Labels: ready-for-agent
Blocked by: none

## Objective

依据 [规格](../spec.md) 将新闻索引维护移至采集端，取消 Agent 首次请求的新闻列表预加载，完成自主文件检索、按需可信引用校验和目录权限适配。

## Scope

- 来源索引的发布时间过滤与采集流程维护。
- 运行开始时固定新闻窗口、精简提示词及目录说明。
- 自主检索入口、最终按需引用校验、子 Agent 与固定评估适配。
- 新闻目录只读、本次工作目录可写的文件服务和沙箱权限。
- 对应测试及现有说明更新。

## Design Status

用户已确认按发布时间筛选且缺失排除、按实际运行开始时刻固定 24 小时窗口。

用户已确认 Q3–Q5 均采纳推荐：文件工具与 bash 均可写整个本次工作目录，CAS 仅约束文件工具写入；每次实际采集尝试结束均维护索引，允许两次维护间暂留过期项并在发布时强制校验；跨快照累计 24 小时内新闻、去重保留到过期。

实现已完成。沿用规格中的采集、运行与真实沙箱测试边界；读取采集端实时索引，固定本次运行的时间窗口。采用含两端的 24 小时窗口，发布时间缺失、无效或晚于开始时刻均排除。旧数据索引在后续采集时补建，不在 Agent 启动时补建。

## Acceptance

1. 采集端拥有每源索引；Agent 启动不重建新闻索引。
2. 模型首条输入保留偏好、明确时间与目录说明，不嵌入新闻条目列表。
3. Agent 可经自主工具调用找到新闻并发布带可信来源的简报；未知发布时间及窗口外内容不能发布。
4. 新闻存储不可写，文件工具与 bash 均可读写整个本次工作目录，其他运行目录不可访问；write_file 的 CAS 检查保留，不约束 bash 直接写入。
5. 每次实际采集尝试结束均维护索引，包括失败、304 和内容不变；两次维护间暂留过期项不影响最终发布时间校验。退出上游列表但仍在 24 小时内的新闻继续保留，重复采集不产生重复项；索引读取一致性的实现决定被记录并具有对应行为测试。
6. 子 Agent、固定评估及已有恢复与发布行为完成相关验证；实际未执行的验证明确标记。
