# 来源新闻索引与 Agent 自主检索

日期：2026-09-19
状态：Q1–Q5 均已确认；实现、行为验证与双轴审查完成。
标签：ready-for-agent

## Problem Statement

用户希望收到与个人偏好相关、在最近 24 小时内发布的新闻。目前 Agent 启动时将所有启用来源的最新快照条目汇总为新闻证据列表，把标题、链接、摘要等嵌入首条用户消息。该步骤没有筛选发布时间，导致旧闻占用上下文并增加 token 消耗，也让 Agent 在开始检索前就接收大量无关内容。

代码核查修正了一点：当前加载的是每个来源的最新快照，不是所有历史快照。最终结果虽有部分时间校验，但允许发布时间缺失的新闻通过，而且时间基准取任务创建时间，未必是实际运行开始时间。

现有引用验证依赖预加载证据列表。因此，采集端索引、运行输入、文件访问、引用验证与沙箱权限需要共同调整。

## Solution

每个新闻来源在采集完成后维护自己的来源新闻索引，收录最近 24 小时内发布的新闻，并从索引剔除过期条目。发布时间缺失的新闻不进入索引，不以采集时间或热榜更新时间替代。

Agent 启动时读取用户新闻偏好和精简的环境说明，不构建新闻证据索引，也不预加载新闻列表到提示词。提示词提供当前日期、实际运行开始时刻、固定的运行新闻窗口及明确时区，并解释新闻存储目录、索引、正文和本次工作目录的含义。

Agent 在自主工具循环中决定查看哪些来源索引、搜索什么关键词、读取哪些文件和哪些行。系统在产出阶段根据选中的新闻证据按需核验来源与时间，保证推送内容可追溯且符合固定窗口。

新闻存储目录对 Agent 只读，文件工具和 bash 均可读写整个本次运行工作目录；其他运行的目录不在授权范围内。write_file 保留 CAS 覆盖检查，该检查不约束 bash 的直接写入。

每次实际采集尝试结束均维护索引，包括失败、304 和内容未变化。允许两次维护之间暂含过期项，Agent 按固定窗口筛选，最终发布时强制校验。索引累计该来源已采集到的最近 24 小时新闻并去重，不因新闻退出上游最新列表而删除。

## User Stories

1. 作为新闻读者，我希望简报只包含最近 24 小时内发布的新闻，以便了解近期变化。
2. 作为新闻读者，我希望发布时间未知的新闻被排除，以免采集时间被误认为发布时间。
3. 作为新闻读者，我希望延迟采集到的旧新闻不会进入简报，以免收到过时内容。
4. 作为新闻读者，我希望 Agent 按我的话题、关键词和背景判断相关性，以便得到符合个人偏好的新闻。
5. 作为新闻读者，我希望没有匹配新闻时保持无匹配结果，以免系统为凑数放宽偏好或编造内容。
6. 作为新闻读者，我希望每条简报可以追溯到真实新闻来源，以便核实信息。
7. 作为系统运营者，我希望索引由采集流程维护，以免每位用户运行 Agent 时重复整理相同新闻。
8. 作为系统运营者，我希望各来源分别维护索引，以便 Agent 有选择地检索。
9. 作为系统运营者，我希望过期新闻从索引移除，以免陈旧材料持续扩大候选集合。
10. 作为系统运营者，我希望首次模型请求不包含完整新闻列表，以减少不必要的输入 token。
11. 作为系统运营者，我希望 RSS 与 NewsNow 等已采集来源均能通过目录说明被发现，以免某类来源遗漏。
12. 作为检索 Agent，我希望提示词说明来源目录和索引文件的含义，以便自主选择检索入口。
13. 作为检索 Agent，我希望知道带时区的运行时刻与窗口起止点，以便一致地判断新闻时效性。
14. 作为检索 Agent，我希望自主决定关键词和来源范围，以便逐步找到相关新闻。
15. 作为检索 Agent，我希望只读取所需文件与内容片段，以便控制上下文消耗。
16. 作为检索 Agent，我希望索引能定位原始新闻证据，以便进一步读取和准确引用。
17. 作为检索 Agent，我希望能够在本次工作目录保存草稿和产物，以便完成简报编写。
18. 作为系统运营者，我希望 Agent 无法修改采集到的新闻，以便保存可信的来源材料。
19. 作为系统运营者，我希望 Agent 无法访问其他运行的工作目录，以便保持运行隔离。
20. 作为系统运营者，我希望禁用来源继续受到授权边界约束，以免新的目录访问方式绕过来源控制。
21. 作为新闻读者，我希望一次运行始终采用相同时间窗口，以免检索和最终校验使用不同的“最近 24 小时”。
22. 作为系统运营者，我希望真实引用仍能在取消证据预加载后通过校验，以免有效检索结果被错误拒绝。
23. 作为系统运营者，我希望伪造、缺失时间或窗口外的引用不能发布，以便维护简报质量。
24. 作为评估维护者，我希望固定资料与固定时钟的评估继续可用，以便比较新旧检索流程。
25. 作为系统运营者，我希望子 Agent 采用相同的检索入口和授权边界，以免它们重新引入全量提示词或扩大访问权限。

## Implementation Decisions

### 用户已确认

- **新闻时间**：按新闻发布时间判定；发布时间缺失则排除，不使用首次发现时间、采集时间或热榜更新时间兜底。
- **运行新闻窗口**：固定为实际 Agent 运行开始时刻向前回溯 24 小时。任务排队时间不作为实际开始时间；本次运行的后续检索沿用同一窗口。
- **索引责任**：来源新闻索引归采集端维护，每个来源单独拥有索引；Agent 启动过程不承担索引构建。
- **模型输入**：移除首条用户消息中的完整新闻列表，保留用户新闻偏好、明确时间和目录使用说明；不将同一列表转移到系统消息规避此要求。
- **检索控制**：Agent 自主选择索引、关键词、文件及阅读范围，不预设固定检索顺序。
- **访问范围**：新闻存储目录只读，本次运行工作目录可读写。权限必须由文件服务和沙箱实际执行。
- **工作区写权限（Q3）**：文件工具和 bash 均可写整个本次工作目录；write_file 保留 CAS 检查，但不宣称其约束 bash 的直接写入。
- **维护触发与时效（Q4）**：每次实际采集尝试结束均维护索引，包括失败、304 和内容不变；允许两次维护间暂留过期项，Agent 按运行新闻窗口筛选，最终发布强制校验。不新增独立定时清理任务。
- **索引集合（Q5）**：累计该来源已采集到的 24 小时内新闻并去重，新闻退出上游最新列表后仍保留到过期。

### 技术落点与实现建议

以下是根据已确认需求及现有实现提出的技术方案，不冒充新的用户确认。

1. **采集服务与采集任务**：复用现有单源串行采集边界，每次实际采集尝试结束均维护索引并完整发布，避免 Agent 读到半写文件。按已确认的 Q5 合并既有索引与本次有效新闻，去重并清理过期项。失败、304 和内容不变也须执行过期维护；保留不可变新闻快照，索引剔除不等于删除历史正文。
2. **索引记录**：包含稳定新闻标识、标题、来源身份、发布时间及可定位可信新闻证据的引用，并提供维护时间。正文按需读取，不把整篇文章复制成索引内容。文件格式、字段名称及路径命名由实现时选择，不在本规格冻结。
3. **时间处理**：实现采用包含两端的 24 小时窗口，发布时间归一化后比较，拒绝晚于运行开始时刻的新闻，取消原有未来 5 分钟宽限。无法解析的发布时间按未知处理。
4. **运行装配**：持久保存实际开始时刻和窗口；同一运行恢复时沿用。可以保存必要的来源授权与证据定位信息，但不复制全部新闻为每次运行构建新索引。
5. **提示词与工具**：更新原先“先使用内嵌索引”的说明，解释索引、正文、来源元信息和工作区的区别。沿用现有列目录、关键词搜索、分行读取及命令工具；保留返回量限制与截断提示，不规定唯一调用轨迹。
6. **按需引用校验**：将最终引用检查从“必须存在于预加载字典”改为按所选证据标识解析可信采集记录，核验来源、URL 与发布时间。Agent 在可写工作区生成的内容不能成为权威新闻证据。
7. **来源授权**：沿用启用来源的使用边界，不能简单开放包含禁用来源的整个宿主目录。来源配置发生身份变化时，新索引不得混入原配置的条目。运行中途禁用的即时生效策略沿用既有授权语义，不在本次扩大范围。
8. **文件服务与沙箱**：所有工具遵守新闻只读规则，文件工具与 bash 均可读写整个当前运行工作目录；运行元信息与凭据不因工作目录可写而暴露。write_file 保留 CAS 覆盖检查，bash 的直接写入不受该检查约束，不再宣称所有持久写入均经过 CAS。
9. **子 Agent 与评估**：同步去除子 Agent 的全量新闻输入。固定资料评估继续使用固定资料和时钟，通过相同的检索和引用验证行为适配，不追随实时采集数据。
10. **既有数据**：旧数据缺少新索引时，在后续采集流程建立索引，不在 Agent 启动阶段补建。缺少新目录快照时清除旧条件请求信息，获取完整响应；无索引的来源被记录为缺失。升级前已绑定证据的旧运行保留其冻结资料与时钟，适配成只读固定资料目录，不重新扫描新闻源。
11. **兼容性与文档**：不预设新增用户端参数或公开 API。同步更新与新行为冲突的提示词、沙箱说明及维护中的实现文档，不改写历史冻结基线。

## Testing Decisions

### 测试边界

优先复用现有“采集任务 → 真实存储 → Agent 运行 → 引用校验 → 简报发布”的业务入口。使用固定时钟、临时新闻存储、模拟上游响应和明确标为模拟的模型输出，运行真实采集与工具循环实现；不通过给 Agent 注入完整新闻列表绕开待测检索行为。

只断言可观察结果：索引可检索内容、发送给模型的消息、工具权限、最终引用、发布结果和恢复行为。不测试内部辅助函数名称、私有调用次数或固定检索顺序。真实 Linux 容器权限作为必要的独立边界验证，不能由文件工具单元测试代替。

用户随后调用 implement，实施沿用本规格中已展示的业务入口与真实沙箱测试边界，按行为切片执行 TDD。

### 行为覆盖

1. **发布时间**：覆盖窗口内、恰好边界、过期、未来、缺失及不同明确时区的发布时间；采用包含两端的 24 小时窗口。今天采集到的三天前新闻不得入选。
2. **固定窗口**：任务排队后执行，按实际开始时刻确定窗口；检索耗时或同一运行恢复不得推动窗口。
3. **来源索引**：不同来源独立维护，索引和证据引用对应；过期清理不删除历史正文。新闻退出上游最新列表后，只要仍在 24 小时内就继续保留；重复采集或重新出现不会产生重复索引项。
4. **采集结果**：覆盖成功、部分条目有效、304、内容不变及失败，验证每次实际采集尝试结束均清理过期项。允许两次维护间暂留过期项，但最终发布不得放行运行窗口外新闻；失败不覆盖有效采集数据。
5. **一致性**：扩展现有并发采集、租约失效和发布中断用例，读取者不能获得半写索引或索引定位不到的已宣告证据。
6. **消息与成本**：截获模型首次请求，验证偏好、窗口和目录说明存在，新闻条目及摘要未批量嵌入。增加同一来源的新闻数量时，首次请求不应随条目数线性膨胀；不承诺未经测量的整体 token 节省比例。
7. **自主检索闭环**：模拟模型通过不同合法工具路径找到新闻并生成简报；不要求每次都先列目录或固定检索次数。
8. **可信引用**：合法文件检索结果通过按需校验；伪造标识、被篡改的工作区副本、未知时间、过期或未来新闻不能发布；没有匹配内容不凑数。
9. **权限**：新闻目录的创建、覆盖和删除均被拒绝；允许本次工作区内约定的写操作；不能访问其他用户或运行目录。沿用现有路径穿越、链接越界及文件覆盖冲突用例。
10. **命令沙箱**：真实 Linux 容器中验证新闻只读、bash 对整个本次工作目录可写并实际落盘，且其他运行目录不可访问；明确 CAS 仅保护文件工具写操作。
11. **授权与配置变化**：禁用来源不通过新目录入口重新暴露；修改来源配置后不混用旧索引。
12. **相关入口**：子 Agent 不收到全量新闻输入；固定评估不读取实时资料；既有发布幂等、取消和恢复行为保持有效。

### 现有测试先例

- 采集服务已有条件请求、内容不变、无效响应、首次发现时间、快照发布失败及提交中断恢复用例。
- 采集任务已有同源并发、单一网络执行者、过期租约和持久化结果用例。
- 运行服务已有模拟模型驱动真实 create_agent、数据库、文件与发布流程的集成用例，可扩展为新检索闭环。
- 文件服务已有只读新闻目录、CAS 冲突、跨主体写入、路径穿越及链接越界用例。
- Harness 已有真实命令容器、子 Agent 恢复及固定资料评估用例。

实际验证结果记录在实施任务中；模拟模型测试不代表真实供应商新闻质量验收。

## Out of Scope

- 不执行真实新闻推送或生产部署；实现及当前分支提交由用户随后调用的 implement 技能授权。

- 不恢复长期记忆，不更改偏好配置、推送计划、投递渠道或双端视觉。

- 不重构评估平台或新增成本仪表盘。

### 尚需在实现方案中处理的衔接

- **固定窗口与可变索引**：实现读取采集端实时索引，运行时不复制或构建索引；候选集合可随采集变化，运行时间窗口保持固定。已选引用从不可变采集记录按需解析，即使索引已移除该项仍可核验。精确重放候选集合不在本次范围内，固定评估继续使用冻结数据。
- **旧文可见性**：索引不含过期新闻，不等于物理存储中没有历史正文。无论检索范围如何实现，最终推送必须符合已确认的发布时间规则。
- **时间未知来源**：NewsNow 等来源可能不给出新闻发布时间；按已确认规则，这类条目被排除，即使刚进入热榜也不例外。
- **沙箱规范差异**：旧实现仅文件工具可写输出区域，bash 持久挂载只读。Q3 已明确替换为文件工具与 bash 均可写整个本次工作目录，CAS 仅约束文件工具写入；实施时同步更新对应说明与测试。
- **交付标记**：ready-for-agent 表示规格已进入本地任务系统；Q1–Q5 均已确认，实施技术选择已记录，测试与审查结果另在实现任务登记。
