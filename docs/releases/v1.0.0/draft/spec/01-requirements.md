## 建议的业务规则

- 正式 Agent 按话题、背景与关键词理解相关性；原型筛选命中任一所选话题或任一关键词即可入选，不要求同时命中。至少一个话题或关键词，背景可空且最长 500 字；关键词最多 20 个、每个最长 40 字。背景在原型中只保存，不假装完成模型语义筛选。界面不提供匹配模式、排除词或来源设置。原型内部采用最近 24 小时、最多 10 条、全部三类来源、中文标准摘要，运行预算与高级参数由系统和管理员配置。
- 没有匹配内容不静默放宽偏好、不填充假新闻。部分来源失败且有足够证据时允许 `partial`；全部失败/证据不足时明确失败或无匹配。
- 新闻热榜排名、抓取时间不能充当新闻发布时间；未知发布时间显式保留 unknown，并在严格时效模式中排除或标记。
- 手动“重新生成”新建内容版本；管理端重试站内发布引用同一简报。调度与重复点击使用唯一业务键，避免重复运行和重复发布。
- 每日自动推送在首次有效偏好保存后启用，默认 08:00；按系统时区 Asia/Shanghai 解释。保存时间不立即生成，不补发历史槽位。站内 submitted 表示已发布，不表示已阅读。
- 用户端没有暂停开关；取消本次运行不改变每日计划。禁用用户的管理操作停止后续调度，恢复只安排下一次有效槽位。
- `read_file` 对不存在文件报错；`write_file` 支持显式创建新文件，仅限存在的合法父目录并用排他创建，已存在文件必须先读。不能一边要求写新闻文档一边禁止所有新建。
- 用户手动偏好高于推断的长期记忆；长期记忆仍按用户隔离，来源与删除机制保留在服务能力中，不在本轮用户偏好表单展示，不把网上内容当作用户事实。
- 管理端评估结果区分规则检查、人工评分和 LLM 评分，不把模型自评作为已证实准确率。

## 首版边界

包含上述用户全部明确要求。采用单服务后端代码库和独立 worker 进程，不强制微服务拆分。默认 Linux 容器部署，数据在 MySQL 和本地持久卷中。

本版不主动增加微信/钉钉/移动原生应用、付费订阅、推荐训练平台、向量数据库、用户自建插件市场；收藏与个人 RSS 管理作为后续增强，不做可点击空壳。

未决技术事项不妨碍原型：MySQL checkpointer 版本兼容、NewsNow 实例选择与可达性、真实模型/Tavily 配置、沙箱平台的行为测试。它们必须在后端验收前解决，不能凭调研文档宣告已通过。
