## 建议的业务规则

- 主题允许语义匹配；包含关键词提供“优先”和“必须至少命中一个”两种模式。排除词优先，在规范化标题与可用正文中做 NFKC + casefold 字面匹配；首版不声称支持正则或布尔查询。原型中应显示规则示例。
- 没有匹配内容不静默放宽偏好、不填充假新闻。部分来源失败且有足够证据时允许 `partial`；全部失败/证据不足时明确失败或无匹配。
- 新闻热榜排名、抓取时间不能充当新闻发布时间；未知发布时间显式保留 unknown，并在严格时效模式中排除或标记。
- 手动“重新生成”新建内容版本；“重试推送”引用同一简报。调度和重复点击有唯一业务键，避免重复运行；外部邮件交付不能承诺绝对 exactly-once。
- 不在开启每日任务时立即发送测试邮件。SMTP 接受仅为 submitted，没有回执不能显示 delivered。
- 暂停停止未来调度，默认不删除历史或取消已经运行的任务；后者有单独取消入口。恢复只安排下一次运行，不补发所有遗漏。
- `read_file` 对不存在文件报错；`write_file` 支持显式创建新文件，仅限存在的合法父目录并用排他创建，已存在文件必须先读。不能一边要求写新闻文档一边禁止所有新建。
- 用户手动偏好高于推断的长期记忆；记忆能查看/删除，不把网上内容当作用户事实。
- 管理端评估结果区分规则检查、人工评分和 LLM 评分，不把模型自评作为已证实准确率。

## 首版边界

包含上述用户全部明确要求。采用单服务后端代码库和独立 worker 进程，不强制微服务拆分。默认 Linux 容器部署，数据在 MySQL 和本地持久卷中。

本版不主动增加微信/钉钉/移动原生应用、付费订阅、推荐训练平台、向量数据库、用户自建插件市场；收藏与个人 RSS 管理作为后续增强，不做可点击空壳。

未决技术事项不妨碍原型：MySQL checkpointer 版本兼容、NewsNow 实例选择与可达性、真实模型/SMTP/Tavily 配置、沙箱平台的行为测试。它们必须在后端验收前解决，不能凭调研文档宣告已通过。
