# 来源后台刷新与持久批量删除

Type: task
Status: resolved

用户已确认第一轮和第二轮全部建议，设计边界已达成一致。实现与验证已完成，结果见 [verification.md](verification.md)。

## 确认的行为

1. 首次加载、翻页加载与后台刷新分开；轮询不禁用操作、不清空选择或覆盖输入。查询变更和写操作使旧读取失效，写操作结束后重新同步。
2. 两个删除入口创建同一种持久任务，全系统最多一个活动批次；离页不取消，回页恢复进度，活动期间禁止再次批量删除。
3. 创建任务时固定候选 ID 与名称。全量失效删除逐项重验，恢复或忙碌项跳过，不在本轮反复重试；新增失效项留待下次。
4. 非目标来源可正常操作；待处理或处理中的目标不能编辑、启停或手动采集。已跳过或失败项恢复相应操作。
5. 列表上方展示真实处理进度、删除/跳过/失败计数、逐项名称与原因，每秒尝试查询，未结束请求不重叠。保留最近一批结果至下一批开始。
6. 断网只影响观察，不判定任务失败；工作进程重启后继续未完成项，已完成项不重复清理。单项失败不阻断其他项；无法继续的整批任务明确失败结束并释放活动名额。
7. 编辑保留草稿，提交检查配置版本；其他管理员修改后拒绝覆盖，提供核对最新配置的方式，来源已删除则明确提示。
8. 清理范围沿用 ADR 0001；单项文件清理和数据库提交都完成后才显示已删除。进度百分比按处理数计算，跳过不是删除成功。

## 实现与验收

- 复用 Celery / Outbox，独立删除任务与明细持久化，数据库唯一约束保证活动批次唯一。
- 每项独立事务，来源文件锁覆盖该项提交；不在管理员请求事务内清理文件。
- 回归覆盖：轮询期间可操作、旧读取不能覆盖操作结果、编辑冲突、任务恢复、重复投递、部分跳过/失败、全局互斥、非目标可操作、来源锁与提交边界。
- 执行契约生成检查、类型检查、管理员构建、适用的后端测试与浏览器验证。
- 不执行实际业务数据删除，不修改用户已有的其他功能变更。
