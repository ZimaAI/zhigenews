# 管理员新闻来源搜索、分页、失效处理与批量管理

Type: task
Status: claimed
Labels: ready-for-agent

本规格发布于项目本地 Markdown 任务系统。业务范围来自已完成的需求讨论；实现与验证进度见 [实现任务](issues/01-implementation.md)。

## Problem Statement

管理员需要在大量新闻来源中按名称查找目标，并直接访问指定页。现有列表仅过滤已加载的数据，依赖“加载更多”，无法准确表达全量搜索结果或直接跳页。

现有采集一次失败就显示失败并持续重试，无法区别暂时失败与经过两次退避重试仍不可用的来源。管理员只能逐条启停，缺少跨页多选、批量删除、全量清理失效来源以及可靠的停止采集操作。

删除正在采集的来源可能与任务写入冲突。管理员需要看到实际停止结果，在停止后清理来源记录、历史快照和采集文件，而不是只从列表隐藏来源。

## Solution

管理员在新闻来源页面按名称搜索全部来源，保留类型筛选，每页固定 10 条，使用上一页、下一页和页码跳转浏览结果。搜索由回车或“搜索”按钮提交；搜索条件或类型改变后回到第一页并清空选择，普通翻页保留选择。

首次采集失败后按既有退避规则重试；连续两次退避重试仍失败，即首次失败加两次失败重试，将来源标记为“失效”并停止自动采集。管理员可手动重试恢复。健康状态与启用状态独立，停用不清除失效标记。

管理员可以跨页选择来源并批量停用或删除，也可以一键删除数据库中全部失效来源，包括已停用的失效来源，不受当前搜索、筛选或页码影响。

正在采集的来源提供“停止采集”操作。停止请求同时停用来源，页面先显示“停止中”，实际采集退出后才确认“已停止”并允许删除。删除会清理来源配置、关联采集记录、历史快照和历次配置的采集文件。已生成简报保留；删除不等待仍读取这些文件的简报任务完成，接受相关运行可能失败。

## User Stories

1. 作为管理员，我希望按新闻来源名称搜索数据库中的全部来源，以便找到尚未加载到页面的记录。
2. 作为管理员，我希望搜索只匹配名称，以便不会因 ID、来源标识或 URL 命中而看到无关结果。
3. 作为管理员，我希望回车或点击“搜索”后应用条件，以便明确控制搜索时机。
4. 作为管理员，我希望搜索与来源类型筛选共同生效，以便缩小结果范围。
5. 作为管理员，我希望每页固定显示最多 10 条来源，以便保持稳定的列表长度。
6. 作为管理员，我希望看到结果总数、当前页和总页数，以便了解搜索范围。
7. 作为管理员，我希望使用上一页和下一页，以便连续浏览结果。
8. 作为管理员，我希望输入有效页码直接跳转，以便快速访问远处的记录。
9. 作为管理员，我希望首页、末页与无结果时的分页按钮正确禁用，以便不会进入无效页。
10. 作为管理员，我希望更换名称搜索或类型筛选后返回第一页，以便看到新条件下的有效结果。
11. 作为管理员，我希望翻页后保留已选来源，以便跨多页组织一次批量操作。
12. 作为管理员，我希望看到已选来源总数，以便了解批量操作影响的范围。
13. 作为管理员，我希望变更搜索或类型筛选后清空选择，以便不会误操作旧条件中的记录。
14. 作为管理员，我希望批量停用所选来源，以便一次暂停多个来源的后续自动采集。
15. 作为管理员，我希望批量删除所选来源，以便清理选定的来源及采集历史。
16. 作为管理员，我希望一次采集失败先进行退避重试，以便暂时性故障不会立即被判为失效。
17. 作为管理员，我希望两次退避重试均失败后明确显示失效，以便识别持续不可用的来源。
18. 作为管理员，我希望任一次成功采集清零连续失败次数，以便恢复成功的来源不会累积旧失败而失效。
19. 作为管理员，我希望失效来源停止自动采集，以便不再持续触发无效请求。
20. 作为管理员，我希望手动重试失效来源，以便在上游恢复后重新使用它。
21. 作为管理员，我希望停用和失效分别表达，以便停用不会掩盖来源此前的失效状态。
22. 作为管理员，我希望一键删除数据库全部失效来源，以便不必逐页选择，且不会遗漏已停用项。
23. 作为管理员，我希望删除前看到对象范围、数量和清理影响，以便知道历史快照与采集文件也将被删除。
24. 作为管理员，我希望对正在采集的来源发出停止请求并同时停用，以便停止后不会被自动调度立即启动。
25. 作为管理员，我希望区分“停止中”和“已停止”，以便判断何时可以删除。
26. 作为管理员，我希望系统拒绝删除仍在采集或停止中的来源，以便不会与采集写入发生冲突。
27. 作为管理员，我希望批量操作报告成功项、未完成项及原因，以便停止采集或排除错误后重试。
28. 作为管理员，我希望删除后更新总数并回到有效页，以便不会停留在因删除而消失的页码。
29. 作为管理员，我希望已生成简报仍能展示内容与原文链接，以便删除来源不会连带删除历史简报。
30. 作为管理员，我希望删除影响如实说明快照不可再查看、相关评估样例不能重跑以及生成中简报可能失败，以便了解清理的后果。
31. 作为管理员，我希望区分加载、无来源、搜索无结果、请求失败和部分完成，以便选择正确的下一步操作。
32. 作为使用键盘或移动设备的管理员，我希望搜索、选择、翻页、停止和删除均可用，以便完成相同的管理任务。

## Implementation Decisions

### 列表查询与选择

- 修改管理员新闻来源列表、来源管理应用服务及共享 API 契约和客户端类型。分页和搜索在服务端对全量来源执行，不能预先截取当前页再过滤。
- 列表接口支持名称搜索、来源类型及页码，来源页面页大小固定为 10；响应提供记录、总条数及计算有效页码所需信息。按现有创建时间与唯一标识倒序保持确定性排序。其他资源列表的游标分页不在修改范围。
- 搜索只匹配名称，采用包含匹配；空搜索表示全部名称。提交搜索时保留类型筛选。内部来源标识可用于稳定选中和接口定位，但不成为搜索字段。
- 页码只接受有效正整数，超过总页数时给出明确反馈；零结果时不提供可执行的翻页或跳页操作。因删除而越界时回到最后有效页，无记录时显示空态。
- 选择集合按来源身份保存，翻页不清空；已应用的名称或类型条件变化时清空。明确显示累计已选数量，批量操作仅传递用户实际选择的来源，不把“当前页全选”解释为全部搜索结果。
- 删除按钮区分“删除所选来源”和“删除全部失效来源”，后者明确标注数据库全量范围。删除确认说明数量及历史数据清理影响；请求失败保留仍有效的选择与筛选。

### 采集失败、失效与恢复

- 扩展来源的持久化状态及公开契约，使启用状态、采集健康状态和正在采集／停止中的执行状态能够分别表达，避免停用覆盖失效判定。
- 复用现有失败计数、有效采集周期及退避机制。首次失败后的等待以有效周期 B 为基础，第一次重试失败后的等待以 2B 为基础，沿用现有抖动、上限及更长的上游 Retry-After；不增加新的退避配置界面。
- 首次失败与第一次重试失败仍属于可重试阶段；第二次重试失败进入失效，阻止自动调度及已排队自动任务继续采集。未采集、快照过期和单次失败不等同失效。
- 成功采集包括有效的未修改响应，清零连续失败次数并恢复健康。失效来源允许显式手动重试；手动成功不会自行解除管理员设置的停用。
- 管理员停止任务不计为一次来源采集失败；沿用来源请求／解析错误与 worker 基础设施故障的区分，不以 worker 重启或数据库错误直接判定来源失效。
- 升级现有记录时以已有采集失败计数识别是否达到失效阈值，不能把旧的公开“失败”状态全部视为失效；已有停用状态保留。

### 停止采集

- 新增来源级停止操作，持久化停止意图并同时停用来源，阻止后续自动调度及尚未开始的旧排队任务执行。
- 复用既有采集文件锁、任务租约和发布检查，在实际采集过程中协作响应停止。不能仅凭停止请求已受理、租约过期或前端超时就报告“已停止”。
- 停止完成意味着该次采集已经退出写入区并释放占用；完成后不得继续发布快照、更新索引或写回数据库。没有运行中采集时，停止操作仍可完成停用并返回已停止。
- 网络读取阻塞期间可能需要等待返回或超时才响应停止。前端持续表达真实状态，不承诺固定停止秒数，不新增强杀 worker 机制。
- 普通停用暂停后续自动采集；停止采集额外终止当前采集。需要删除正在采集的来源时，先使用停止采集，再在确认已停止后执行删除，不自动取消简报生成任务。

### 批量操作与物理删除

- 提供按选中来源批量停用、按选中来源批量删除和全量删除失效来源的管理接口。复用现有管理员身份、权限校验及写操作保护。
- 全量删除在服务端按失效判定查询候选，包含停用的失效来源，不依赖前端已加载列表，也不接收搜索条件来限制范围。执行时重新核实来源状态，不删除已恢复健康的来源。
- 删除须与该来源采集共用互斥边界，再次核实采集已停止；仍在采集或停止中的项不删除，批量结果列明原因，其余满足条件的项正常处理。
- 清理来源配置与私有调度状态、关联采集记录、历史快照，以及该来源历次配置的原始响应、解析文件、快照清单与新闻索引。停止与删除后，旧排队任务不得重新创建该来源或发布已删除数据。
- 数据库与文件删除不能被当作天然的单次事务；只有应清理的数据完成清理才能报告删除成功，未完成项明确返回并允许重试。不额外引入独立清理平台。
- 保留既有简报展示内容和原文链接，不连带删除简报或评估样例。历史快照被删除后不可查看，引用它的评估样例无法再次运行，应如实返回不可用原因。
- 删除不等待读取同一来源文件的简报任务结束，不将“简报仍在生成”作为拒绝删除条件。允许这些任务因文件删除而失败，按照现有任务错误机制呈现。
- 沿用管理员界面规范、共享组件和状态呈现；本次不改变全局视觉风格。

## Testing Decisions

### 测试边界

优先复用现有最高层边界，验证用户可观察的结果，不对内部函数拆分、私有变量布局、调用次数或 CSS 类名编写镜像测试。

1. **主要边界：管理员 HTTP API 集成测试。** 使用现有真实数据库测试夹具和契约探针，通过管理员身份创建来源、查询、停用、停止及删除，验证响应、查询结果和持久化结果。复用现有来源保存／启停／采集契约测试，以及其他列表的分页测试方式。
2. **必要补充：既有采集任务执行边界。** API 响应本身不能证明后台采集已经停止。复用可注入采集器、受控时钟与现有并发任务测试方式，控制任务进入、停止和退出；使用实际临时目录验证发布与清理结果。现有同源任务互斥、旧租约不得发布、异常释放租约、快照落盘与索引测试提供先例。仅在已有采集器边界模拟上游响应，不新增业务测试专用生产接口。
3. **浏览器交互验收。** 验证跨页选择、名称搜索提交、跳页、停止中反馈、删除确认和批量结果；覆盖窄屏及键盘。管理员前端已有类型检查与构建，另复用共享 API 客户端的参数编码、响应与契约同步测试。

上述边界已按 to-spec 流程获得用户确认。测试设计不要求真实外部新闻源持续故障，也不以模拟结果声称真实上游服务已经验证。

### 关键验收场景

- 至少 25 条来源分成 10、10、5 条；覆盖上一页、下一页、合法跳页、无效页码和空结果。名称命中位于原先未加载的记录也应返回；仅 ID 或 URL 命中的记录不返回。
- 搜索与类型共同过滤，数量对应完整结果；改变条件回到第一页并清空选择，普通翻页保留选择。
- 跨页选择两个以上来源，批量停用／删除只影响选中项；成功、仍在采集及其他未完成项分别如实报告。
- 首次失败、第一次重试失败不标记失效；第二次重试失败标记失效且后续自动任务不再采集。中间成功清零；有效未修改响应亦视为成功。
- 失效后手动成功恢复健康；仍被管理员停用时不自动重新启用。停用的失效来源仍被全量删除命中。
- 发出停止请求时任务仍占用采集资源，状态保持停止中且删除不能成功；受控放行任务退出后显示已停止，随后删除成功，后台不再写回。
- 停止后旧排队任务不启动，停止本身不增加失败计数；任务租约过期但仍持有采集占用时不能误判可删除。
- 全量删除涵盖当前搜索以外及其他页的失效来源，健康来源保留；执行前已恢复健康的来源不删除。
- 删除清理数据库关联记录、历史快照和历次配置目录；其他来源的数据不受影响。文件清理未完成时不能返回完整成功，重试能继续处理。
- 已有简报内容及原文链接仍可访问；被删快照明确不可用。生成中简报不是删除阻塞条件，其失败结果不可伪装成功。
- 删除最后一页记录后回到有效页；加载、失败、无数据、无搜索结果、部分完成和停止中不互相冒充。
- 完成针对性后端测试、契约及客户端检查、管理员前端类型检查和构建，并记录浏览器关键交互结果。这里只定义验证计划，不声明已经执行或通过。

## Out of Scope

- 订阅用户列表、用户端页面或隔离原型的修改。
- 按 ID、来源标识或 URL 搜索，以及扩展高级搜索系统。
- 可配置页大小、批量启用、跨搜索条件永久保存选择或全库任意来源一键停用。
- 失效后无限自动重试、新增退避策略编辑界面或保证瞬时停止网络请求。
- 删除来源时等待或主动取消正在生成的简报；删除已生成简报或自动清理历史评估样例。
- 回收站、删除恢复、外部清理平台、全局分页改造或通用任务管理系统重构。
- 自动执行生产数据删除、重新初始化默认来源清单或修改当前产品发布阶段。

## Further Notes

- 统一使用领域术语“新闻来源”；讨论中的“订阅源”和误写的“订阅员”均指该对象。
- 此规格继承已记录的删除采集历史决策：完整清理来源采集数据，保留已生成简报；采集停止即可删除，接受生成中简报可能失败。
- 默认来源不会随普通服务启动自动重建，但显式重新运行默认清单初始化会补入缺失的默认来源。本功能不改写该运维语义。
- 项目任务系统采用本地 Markdown，无既有 triage 标签体系；本条目以 Labels 元数据记录技能要求的 ready-for-agent，不创建外部工单或新标签系统。
- 新 API 的具体路径、字段拼写和数据库存储细节在实现中沿用现有契约与迁移惯例；上述业务语义和可观察验收结果是约束。
- 测试边界核对：用户确认“符合，按这些边界编写规格”。
