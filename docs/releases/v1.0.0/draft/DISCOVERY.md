# v1.0.0 需求与架构评审

状态：DISCOVER 完成范围梳理，等待选择是否进入 ITERATE。未冻结基线，未批准正式实现。调研日期：2026-09-18。

## 要做成什么

用户保存关注主题、关键词和阅读偏好，系统每天按其时区整理一份可追溯来源的 AI 新闻简报，通过站内收件箱和可选电子邮件推送。用户能解释“为什么推荐给我”，也能区分内容生成失败和邮件发送失败。

管理员在独立前端中管理新闻源、模型/端点/密钥、Agent 配置，并从实际运行轨迹和评估对比中调优。两个 Vue 3 项目对接同一个 Python 后端。

## 本轮建议的技术组合

| 部分 | 方案 | 决定来源 |
| --- | --- | --- |
| 后端 | Python 3.12、FastAPI、LangChain `create_agent`、LangGraph | 用户指定核心技术；Python 小版本为建议 |
| 数据库 | MySQL 8.4 LTS 目标环境、SQLAlchemy 2、Alembic | 用户指定 MySQL，其余为建议；本机已有 8.0 客户端不代表服务兼容已验证 |
| 队列/调度 | Celery + Redis；单调度器按 MySQL 中每源/每用户的到期时间派发 | 建议，避免把长时任务放进 HTTP 进程 |
| 前端 | 独立 `user-web` / `admin-web`；Vue 3 + TypeScript + Vite + Router + Pinia | 用户指定分项目与 Vue 3，其余为建议 |
| 新闻 | NewsNow 按源缓存、RSS 原文件与规范化索引、Tavily 搜索 | 用户要求 |
| 推送 | 站内收件箱 + 用户主动启用的 SMTP 邮件 | 用户授权自行选择渠道，本轮选定方案 |
| 运行环境 | Linux 容器；Windows 用 Docker Desktop/WSL2 开发 | 建议，用于隔离 bash，worker 不依赖原生 Windows 支持 |
| 观测 | MySQL 运行/事件/评估记录、SSE 回放；可选外接 LangSmith | 自带管理功能为首版，外部平台不是必需依赖 |

精确依赖版本和锁文件在实施前经兼容验证确定，不把研究时的“latest”作为可复现构建承诺。

## 用户完整主流程

1. 注册/登录，选择主题和包含/排除关键词，保存阅读语言、时间窗口、最大条数、摘要深度。
2. 选择每日时间与 IANA 时区；默认站内阅读，邮件需启用并验证目的地。
3. 手动生成第一份简报，或由每日任务触发。系统冻结本次偏好、配置和来源文件清单。
4. Agent 自主选择读取 NewsNow/RSS 材料、Tavily 搜索、必要时委派子任务，按预算迭代筛选与总结。
5. 工具通过沙箱读文件，在本次工作区用哈希检查写入文档；服务器校验结构、引用和归属后发布简报。
6. 用户阅读标题、摘要、推荐理由与来源；历史保存版本。邮件失败可以重试原简报，不重新生成。
7. 管理员查看这次运行的工具事件、用量、错误与评估结果，发布新配置供后续任务使用。

## 技术调研影响到的关键决定

- NewsNow 的源间隔与全局 TTL 不同，必须保留每源更新时间策略；API 中 `updatedTime` 的部分分支不能直接当成新闻时间或真实抓取时间。详见[新闻采集调研](../../../research/news-ingestion.md)。
- 使用 `create_agent` 的模型—工具循环，不用固定“搜索一次、总结一次”的流水线替代自主 Agent。消息修复和摘要必须按本系统要求扩展，详见[运行时调研](../../../research/agent-runtime.md)。
- `/rss` 只读，`/workspace` 仅属于当前用户当前运行。NewsNow 快照放到本次工作区只读子目录；Agent 无需第三个宿主根目录。
- `bash` 不能直接访问宿主。为保持所有持久写入都经过哈希校验，命令仅能写隔离暂存区，文档最终经 `write_file` 写回。容器只读视图和受控写服务的边界详见[沙箱调研](../../../research/sandbox-observability.md)。
- 每个 AI 消息可以有多个 tool call；按调用 ID 配对，不按消息数量配对。丢失结果补明确失败/取消结果，不能冒充成功。
- 摘要写入专门状态字段；压缩器不负责注入，模型调用中间件负责渲染。旧摘要参与下一轮摘要，最近真实用户输入原文保留，预算包含摘要和工具定义。
- MySQL 持久化保持用户的数据库选型，LangGraph saver/store 的兼容性必须独立验证；不能把内存 checkpointer 作为生产方案。

## 页面范围

用户端：登录/首次配置、今日简报、简报详情、历史、兴趣订阅、推送设置、简化运行详情。

管理员端：运行概览、新闻源及抓取记录、模型/端点/密钥、Agent 配置版本、运行详情与子任务、评估数据集及实验对比、用户状态与投递记录。

收藏和用户自行维护 RSS 订阅目录属于后续增强；首版由管理员维护源，用户设置来源类型/偏好与主题。设计文件也将这两项标为后续增强，未删减用户明确要求。

## 可逆默认值（待原型确认）

| 参数 | 初始建议 |
| --- | --- |
| 首次配置时间与时区 | 08:00，Asia/Shanghai，页面清楚展示并允许修改 |
| 阅读窗口与条数 | 最近 24 小时，最多 10 条，中文，中等摘要 |
| 匹配 | 主题语义匹配；包含词默认优先、可切换“至少匹配一个”；排除词优先过滤 |
| 文件响应限制 | 单次 200 行且 16 KiB，目录/搜索结果默认 50 条，均可调但不超过服务端上限 |
| Agent 预算 | 30 次模型调用、60 次工具调用、8 分钟总时长；管理员可修改，首轮真实实验再定合理值 |
| RSS 轮询 | 无源端提示时 30 分钟起步，有提示和缓存头时按其约束调整 |

上述数字是建议配置，不是已测性能或质量指标。研究笔记可能列出其他示例预算，以这张表作为本轮产品默认值讨论入口。
